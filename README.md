# Порядок — очереди на защиту

Сайт для группы **SE-2421**: своё место в очереди, список защит, недельное расписание и управление для администратора.

**[Открыть сайт](https://heb1ks.github.io/queue-for-defence/)**

Интерфейс размещается на GitHub Pages, а студенты, очереди и права — в PostgreSQL проекта Supabase. Сайт написан на обычных HTML, CSS и JavaScript. Сборщик и установка npm-пакетов не требуются; библиотека Supabase JS **2.118.0** включена в `vendor/` вместе с лицензией.

## Что умеет сайт

- **Мои очереди** — записи студента, место и текущий защищающийся.
- **Все очереди** — поиск по предмету, статусы записи, вступление и выход.
- **Расписание** — недельная сетка на компьютере и просмотр выбранного дня на телефоне. Фильтр ML/CGF сохраняет общие предметы. Нажатие на занятие открывает его время, ближайшую очередь и действия администратора. Часовой пояс группы — `Asia/Qyzylorda`.
- **Управление** — предметы, создание очередей на конкретную дату, расписание и удаление предметов.
- В открытой очереди админ вызывает следующего, убирает отдельного участника, закрывает запись или отправляет очередь в архив.
- Сервер требует **5 секунд между изменениями одного студента**, в том числе при входе с нескольких устройств. Чтение очереди этим интервалом не ограничено.

## Настройка Supabase

Подробные инструкции и SQL находятся в [`supabase/README.md`](supabase/README.md).

1. Создайте проект Supabase. Оставьте Data API включённым; автоматическое открытие новых таблиц для API можно отключить.
2. В **Authentication → Sign In / Providers** включите **Anonymous Sign-Ins**. Это технические сессии сайта; студентам не нужны Google, почта или отдельный пароль Supabase.
3. Выполните [`supabase/schema.sql`](supabase/schema.sql) в SQL Editor от владельца проекта.
4. Добавьте настоящий список студентов по шаблону [`supabase/roster.example.sql`](supabase/roster.example.sql). Хотя бы у одного студента должна быть роль `admin`.
5. Выполните [`supabase/cron.sql`](supabase/cron.sql), чтобы занятия создавались по расписанию без открытого сайта.
6. Укажите Project URL и **publishable key** в [`config.js`](config.js). Старый публичный `anon`-ключ также поддерживается. Этот репозиторий уже подключён к проекту через публичные параметры этого файла.

Настоящий список студентов заполняется **только в панели Supabase**. Не добавляйте его в репозиторий, сборку или примеры. В браузер не должны попадать пароль базы, `service_role` и ключи `sb_secret_…`.

## Вход студентов

Студент вводит имя, фамилию, группу и **свой индивидуальный код студента**. Сервер сверяет данные с предварительно добавленным списком и привязывает сессию к соответствующему профилю. Регистр и повторные пробелы в ФИО и названии группы не учитываются.

При входе с другого устройства сохраняется тот же профиль и место в очереди. Код студента не возвращается участникам в списках очередей. Админские права берутся из приватной записи студента и не назначаются данными формы.

Этот способ входа рассчитан на доверие внутри группы: **код студента — идентификатор, а не секретный пароль**. Зная чужое ФИО и код, можно представиться этим студентом. Для более строгого подтверждения личности понадобится отдельный PIN или иной способ аутентификации.

## Локальный запуск

Нужен **Node.js 22 или новее**. Выполняйте команды из папки репозитория:

```sh
node --test tests/*.test.mjs
node scripts/build.mjs
node scripts/serve.mjs
```

Сайт откроется по адресу, который выведет сервер, обычно `http://127.0.0.1:4173`. Для просмотра именно собранной версии:

```sh
node scripts/serve.mjs --dist
```

Не открывайте `index.html` двойным щелчком: JavaScript-модулям нужен HTTP-сервер. Для остановки сервера нажмите `Ctrl+C`.

## Публикация на GitHub Pages

Репозиторий: [Heb1ks/queue-for-defence](https://github.com/Heb1ks/queue-for-defence).

1. В репозитории откройте **Settings → Pages**.
2. В **Build and deployment → Source** выберите **GitHub Actions**.
3. Отправьте изменения в ветку `main` или запустите **Actions → Deploy Pages → Run workflow**.
4. Дождитесь успешных этапов `build` и `deploy`. Адрес сайта появится в результате развёртывания.

Workflow [`pages.yml`](.github/workflows/pages.yml) выполняет тесты, собирает сайт и публикует **только `dist/`**. В эту папку не копируются SQL, инструкции импорта или тестовые файлы. Пути к ресурсам относительные, навигация использует `#/…`, поэтому сайт поддерживает адрес с подпутём репозитория.

Публичные настройки можно переопределить без редактирования `config.js` через **Settings → Secrets and variables → Actions → Variables**:

| Переменная | Значение |
| --- | --- |
| `SUPABASE_URL` | HTTPS-адрес проекта `https://…supabase.co` |
| `SUPABASE_PUBLISHABLE_KEY` | Публичный publishable key или старый `anon`-ключ |

Эти значения предназначены для браузера и будут доступны посетителям. Сборка отклоняет secret-ключи и старые JWT с ролью `service_role`.

## Демо и общая база

Кнопка **«Посмотреть демо»** открывает пример кабинета с вымышленными участниками. Баннер явно обозначает демонстрацию. Её изменения сохраняются только в браузере и не создают очередей в Supabase.

Обычный вход работает с общей базой группы. Данные обновляются через Realtime; при недоступности Realtime используется резервная проверка раз в 30 секунд. В скрытой вкладке подписка и резервные запросы приостанавливаются, при возвращении список обновляется.

## Расписание и ограничения

Админ задаёт предмет, день недели, время занятия, момент открытия записи и длительность. На каждое занятие создаётся отдельная очередь. Cron в Supabase проверяет расписание раз в пять минут; повторный запуск не создаёт дубликатов.

После изменений расписания уже открытые очереди и очереди с участниками сохраняются. Будущие пустые занятия, запись в которые ещё не открылась, могут быть пересозданы по новым настройкам.

Для небольшой группы можно использовать бесплатные тарифы. У Supabase Free есть квоты и возможна приостановка проекта после периода низкой активности. При приостановленной базе очереди и Cron не работают до возобновления проекта. Актуальные условия: [тарифы](https://supabase.com/pricing), [доступность проекта](https://supabase.com/docs/guides/deployment/going-into-prod#availability).

## Проверки

`node --test tests/*.test.mjs` проверяет API-клиент, обработку ошибок, сессии, Realtime, демо-очереди, часовой пояс и безопасность публичной сборки.

Для проверки SQL в PostgreSQL/PGlite есть отдельный сценарий [`supabase/tests/integration.mjs`](supabase/tests/integration.mjs); его запуск описан в инструкции Supabase. Этот тестовый пакет не нужен опубликованному сайту.

Результаты локальных проверок не заменяют проверку реального входа, настроек Auth, доставки Realtime и успешного развёртывания Pages.
